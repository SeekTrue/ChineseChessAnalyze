## 二、关键设计决策

### 1. 胜负标签：从末步推断将死（用户选定方案）
棋谱无胜负字段，`detectCheckmate.m` 通过"末步后被将死/困毙"判定胜负。
- 实测 3000 局中约 **51.6%** 可判定胜负，其余为认输/和棋（无法从棋谱推断，`result=0`）。
- 关键度评分对无标签对局跳过，并对少标签模式降权；胜率用**拉普拉斯平滑**避免极端值。

### 2. 关系编码：移植你的七状态分析思想
`encRelations.m` 把你原有的危/险/疲/困/串/双/游七状态思路统一到 board 矩阵接口，
结合 `attackEngine.m`（移植自 `analyze_danger.m` 的攻击范围算法，含蹩马腿/塞象眼/炮架/九宫/过河）。

### 3. 标签树的认知约束（硬性）
- 树深 ≤ 3，`maxLeaves=80`，L2 分支 K 在 5–9（Miller 魔数）。
- L1 大类手工设定（贴合你的认知习惯），L2 用 Statistics Toolbox 的 `kmeans` 聚类，L3 按关键度 Top-N。
- 命名优先级：传统定式名锚定（中炮/屏风马/出车…）→ 特征自动生成名。

### 4. 关键度评分
`criticality = 0.25·freq + 0.15·phaseWeight + 0.35·|winRate−0.5| + 0.25·docFreq`
（已按无棋手等级的现实调整，去掉 skillGap 项。）

## 六、已知限制与后续方向

1. **认知编码覆盖面**：当前叶节点以开局定式为主（因为开局套路重复度最高）；中局/残局的"结构"多为静态阵型签名，命名较抽象。后续可增强 motif 提取和残局模式。
2. **胜率偏差**：能识别的胜负多为将死局，可能偏向某些激烈结构；认输局的结果无法从棋谱恢复。若能从外部补齐结果表，可按 `game.id`（文件名 ID）关联。
3. **MDL 覆盖率**：受叶节点数上限约束，字典较小。可调大 `cfg.maxLeaves` 观察压缩率变化。
4. **性能**：3000 局约 4 分钟；全量 12 万局建议分批（用 `cfg.maxGames` + 不同 `cfg.randomSeed`）或先做去重。
