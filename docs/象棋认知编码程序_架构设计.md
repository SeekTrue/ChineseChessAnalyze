# 象棋认知编码分析程序 — 架构设计 v1.0

> 目标：从棋谱中挖掘可被大脑当作"基本记忆单元"的高频/关键结构，
> 生成一套分层标签树式的认知编码，从而降低棋局认知负担、提升棋力。

---

## 0. 理论基础与设计原则

本设计基于认知心理学的组块（chunking）理论：象棋高手的记忆优势来自对
棋局结构的组块化编码，而非天生记忆力（de Groot / Simon 的经典实验：
大师对随机摆放的棋子并无记忆优势）。因此本程序的核心不是"记住更多棋谱"，
而是**发现并命名那些值得作为记忆单元的棋局结构**。

三条设计原则：

1. **压缩率必须可量化** —— 用 MDL（最小描述长度）思想衡量编码前后的棋谱描述长度差。
2. **关键度不能只看频率** —— 高频但无信息量的结构（如开局首着）应被降权。
3. **认知负荷必须受约束** —— 标签树深度 ≤3、每层分支数 5–9（Miller 魔数）、叶节点总数受控。

## 3. 第 1 层：中文文字记谱解析规范（技术难点 1）

### 3.1 记谱语法

中文记谱每步由四部分构成：`<棋子><起始纵线><动作><参数>`

- 棋子：红方 帅仕相马车炮兵，黑方 将士象马车炮卒
- 纵线编号：**红方用汉字一~九，黑方用阿拉伯数字 1~9**
- 动作：进 / 退 / 平
- 参数：目标纵线或步数（依棋子类型而定）

### 3.2 统一坐标系（必须严格遵守）

- 棋盘矩阵 `board(10,9)`：`row=1` 为黑方底线，`row=10` 为红方底线
- 红方纵线 N → `col = 10 - N`（红方一路在最右侧 col=9）
- 黑方纵线 N → `col = N`（黑方 1 路在最左侧 col=1）

**校验样例**：红"炮二平五" → 起始 col=8（red 二路），目标 col=5，
应为 `board(8,8) → board(8,5)`；黑"炮8平5" → `board(3,8) → board(3,5)`。

### 3.3 进退语义的关键分歧

| 棋子类型 | 进 / 退 的参数含义 | 行方向 |
|---|---|---|
| 车、炮、兵/卒、将/帅 | **步数** | 红"进" = row 减小，黑"进" = row 增大 |
| 马、士/仕、相/象 | **目标纵线**（斜行，需反推行变化） | 同上 |

- 马的推算：`|Δcol|=1 → |Δrow|=2`；`|Δcol|=2 → |Δrow|=1`；方向由进/退决定
- 士：`|Δcol|=1 → |Δrow|=1`；相/象：`|Δcol|=2 → |Δrow|=2`

### 3.4 歧义与合法性

- 同纵线多个同类棋子：支持"前车/后车""前兵/后兵"前缀消歧
- 走法合法性校验必须实现：蹩马腿、塞象眼、炮翻山、将帅照面、九宫/过河限制
- 解析器应输出结构化走法对象：`{side, piece, fromRow, fromCol, toRow, toCol, action, rawText}`

## 4. 第 3 层：多尺度编码方案

同一局面并行生成三种视角，最终拼接为特征向量：

| 编码 | 内容 | 认知对应 |
|---|---|---|
| 子力编码 | 各兵种数量、位置分布、未兑子情况 | "谁还在场上" |
| 区域编码 | 九宫 / 河界 / 三路七路 / 侧翼的子力密度 | "重心在哪里" |
| 关系编码 | 攻击、保护、牵制、联动的邻接矩阵 | "子力之间怎么配合" |

> 关系编码最能体现"结构"，但计算最贵；MVP 阶段可先实现子力 + 区域。

## 5. 第 4 层：模式挖掘与关键度评分

### 5.1 候选结构的三种来源

1. **静态阵型**：滑动时间窗内的局面子矩阵（如 3×3 局部、整个半盘）
2. **走法序列**：N-gram 走法套路（N=3~8）
3. **战术 motif**：关系矩阵中的特定子图（牵制、闪击、双将等）

### 5.2 关键度评分公式（根据"只有胜负"调整）

```
criticality = α·freq + β·phaseWeight + γ·|winRate − 0.5| + δ·docFreq
```

| 项 | 含义 | 说明 |
|---|---|---|
| `freq` | 出现频率（归一化） | 高频是必要条件，但不是充分条件 |
| `phaseWeight` | 阶段权重 | 开/中/残局分别加权，避免开局套路淹没结果 |
| `\|winRate−0.5\|` | 结果相关性 | **按执红/执黑分别归一化**，否则执红先手偏差会污染评分 |
| `docFreq` | 跨对局复用广度 | 在不同对局中都出现的结构更值得记忆 |

> 因无棋手等级数据，无法做"高手专用结构"分析；若后续补齐等级标签，
> 可增加 `ε·skillGap` 项（该结构在高手局中的频率差）。

**建议初始权重**：α=0.25, β=0.15, γ=0.35, δ=0.25（γ 最高，突出"决定胜负"的结构）。

## 6. 第 5 层：分层标签树（认知核心，重点）

这是本项目区别于普通棋谱统计的地方。树分三层，符合人类认知习惯：

```
Level 1  大类（人工设定，5–9 个）：开局架构 / 中局结构 / 残局定式 / 战术motif / ...
  └─ Level 2  族（半自动聚类，每类 5–9 个）：如 [中局结构] → 侧翼进攻 / 中路突破 / 子力集结 ...
       └─ Level 3  叶节点（具体结构，自动命名 + 人工确认）
```

### 6.1 树的生长方式

- **Level 1 人工设定**：因为它们要贴合你的认知习惯，且数量少
- **Level 2 由聚类产生**：对 Level 1 内的结构特征做 K-means / 层次聚类，K 取 5–9
- **Level 3 由频繁模式产生**：按关键度排序取 Top-N，受总叶节点数约束

### 6.2 命名策略（降低记忆成本的关键）

按优先级依次尝试：

1. **传统定式名锚定**：若匹配已知定式（当头炮、屏风马、铁门栓…），直接沿用
2. **特征自动生成名**：`[核心子力] + [区域] + [关系]`，如"双车-同侧-河界集结"
3. **人工确认**：对高频叶节点给出 2–3 个候选名，由你选定后固化

### 6.3 叶节点数据结构

```matlab
struct('id', ..., 'name', ..., 'parent', ..., ...
       'template', <结构模板/特征向量>, ...
       'freq', ..., 'winRate', ..., 'criticality', ..., ...
       'avgPly', ..., 'exampleGameIds', {{...}}, ...
       'descriptionLen', ..., 'sketch', <棋盘示意图>)
```

### 6.4 认知负荷约束（硬性）

- 树深度 ≤ 3
- 每层分支数 5–9
- Level 3 叶节点总数 ≤ 80（可按你的记忆容量调整）
- 生成后用 MDL 评估：编码后描述长度应显著小于原始走法序列

## 9. 风险与注意事项

1. **中文记谱解析是最大技术风险**：同路多子、错别字、不同平台记谱习惯差异都可能导致解析失败。建议 MVP 阶段先拿 20 局样例做解析正确率校验。
2. **胜负偏差**：胜率高的结构未必"好"，可能是因为它出现在已经赢定的局面。可考虑只统计"胜负未定阶段"（如前 40 回合）的结构。
3. **频率 ≠ 价值**：需人工审视 Top 结构，剔除"废话型"高频模式。
4. **MATLAB 工具箱依赖**：聚类可用 Statistics and Machine Learning Toolbox；若无，可用自实现 K-means 替代。
